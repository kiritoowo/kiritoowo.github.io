CI/CD 调优篇：Git、Maven、Jenkins、GitLab CI/CD、Docker、K8s 与 Ansible

发表于 2025-06-12 | 分类于 调优 ， DevOps

CI/CD 调优目标是更短反馈时间和可重复发布。缓存依赖与镜像层、并行化测试、限制构建资源，并将 SBOM、签名和漏洞门禁纳入流水线。

构建与缓存

# Git 全局配置
git config --global fetch.parallel 8
git config --global core.compression 1
# Maven 并行构建
mvn -T 1C -Dmaven.repo.local=.m2/repository verify
# Docker BuildKit 缓存
RUN --mount=type=cache,target=/root/.m2 mvn -T 1C package

Jenkins Pipeline 使用并行 stage，executor 不超过节点 CPU；GitLab Runner 使用 Docker executor 与缓存。Kubernetes 构建 Pod 设置 requests/limits，镜像用 Trivy/Grype 扫描并 Cosign 签名。

发布流程

flowchart LR A[提交/合并请求]-->B[单测+静态扫描] B-->C[缓存构建] C-->D[SBOM/漏洞门禁] D-->E[K8s 灰度] E-->F[指标验收] F--通过-->G[全量发布] F--失败-->H[自动回滚]

Ansible 使用幂等模块、ansible-lint 和 Vault；K8s Deployment 配置 readinessProbe、PDB 与滚动更新上限，发布前执行 server-side dry-run。

  • Jenkins Pipeline

Ansible 配置

- hosts: ci_runner
  become: true
  tasks:
    - name: 安装构建依赖
      ansible.builtin.apt:
        name: [git, maven, docker.io, ansible-lint]
        update_cache: true
        state: present
    - name: runner 加入 docker 组
      ansible.builtin.user: {name: gitlab-runner, groups: docker, append: true}
    - name: 配置 Docker 日志轮转
      ansible.builtin.copy:
        dest: /etc/docker/daemon.json
        mode: '0644'
        content: '{"log-driver":"json-file","log-opts":{"max-size":"100m","max-file":"3"}}'
      notify: 重启 Docker
  handlers:
    - name: 重启 Docker
      ansible.builtin.service: {name: docker, state: restarted}

APM 调优篇：SkyWalking、ELK Stack、Prometheus 与 Grafana

发表于 2025-04-17 | 分类于 调优 ， 可观测性

可观测性系统也会消耗 CPU、网络和存储。采用采样优先、标签受控、冷热分层，保证故障高峰仍能查询关键链路。

信号与容量基线

系统生产起点关键参数
SkyWalking普通链路 10%，错误 100%agent.sample_n_per_3_secs
Prometheus抓取 15–30s，保留 30 天--storage.tsdb.retention.time=30d
ELKHot 7 天、Warm 30 天、冷归档ILM、bulk pipeline
Grafana查询超时 30s，变量限值缓存与并发查询

降噪与验证

# Prometheus 启动参数
--storage.tsdb.retention.time=30d
--storage.tsdb.wal-compression
# Filebeat 队列参数
queue.mem.events: 4096
bulk_max_size: 2048
compression_level: 5

指标标签禁止 userId、requestId 等高基数字段；日志 pipeline 脱敏。看板按 RED/USE 组织，告警带 runbook。演练 Prometheus 重启、ES 节点故障和采样降级。

分布式框架调优篇：Spring Cloud Alibaba、Nacos、Seata、Gateway、OpenFeign、Sentinel、Sharding-Proxy 与 XXL-JOB

发表于 2025-03-06 | 分类于 调优 ， 分布式

分布式调优首先控制重试和连接总量，把超时、重试、熔断、限流、注册中心和任务调度纳入容量预算，避免重试风暴。

组件基线

组件生产建议
Nacos≥3 节点、鉴权；长轮询 30s，本地快照
OpenFeignconnectTimeout 1s、readTimeout 3s；幂等请求最多重试 1 次
Gateway连接池按下游容量，response-timeout 5s
SentinelQPS+并发双维度限流，规则持久化 Nacos
SeataAT 事务短小，undo 日志清理；强一致评估 TCC
XXL-JOB线程池隔离，错峰触发，失败重试≤2

重试预算流程

flowchart TD U[用户请求]-->G[Gateway 5s] G-->F[Feign 1s/3s 重试1] F-->S[Sentinel 熔断限流] S-->D[下游服务] D-->DB[(数据库连接池)]

ShardingSphere-Proxy 开启 SQL 审计和连接池上限，分片键必须出现在查询条件；跨库事务交由 Seata 或最终一致方案。

OpenResty 调优篇：事件模型、缓存与 LuaJIT

发表于 2024-12-12 | 分类于 调优 ， 网关

OpenResty 基于 Nginx 事件循环和 LuaJIT。调优关键是 worker、连接上限、proxy 缓冲和 Lua 共享字典；请求路径禁止阻塞 I/O。

nginx.conf 基线

worker_processes auto;
worker_rlimit_nofile 200000;
events { use epoll; worker_connections 65535; multi_accept on; }
http {
  sendfile on; tcp_nopush on; tcp_nodelay on;
  keepalive_timeout 30; keepalive_requests 1000;
  proxy_http_version 1.1; proxy_buffering on;
  proxy_buffers 16 16k; proxy_busy_buffers_size 64k;
  lua_shared_dict metrics 20m;
  gzip on; gzip_comp_level 5;
}

Lua、缓存与验收

使用 lua-resty-redis 连接池并调用 set_keepalive；共享字典用于限流和热点缓存。动态接口使用 proxy_cache_lock 抑制击穿，静态资源使用 immutable 长缓存。关注 active/reading/writing、upstream 响应时间、Lua GC、4xx/5xx。

Tomcat 调优篇：线程池、连接器与会话管理

发表于 2024-11-07 | 分类于 调优 ， Web容器

Tomcat 10.1 调优遵循“线程数匹配下游容量”。先用 NIO/NIO2 与共享线程池，再依据 p99、队列和 GC 调整 maxThreads。

连接器基线

<Executor name="tomcatThreadPool" namePrefix="catalina-exec-" maxThreads="400" minSpareThreads="50"/>
<Connector executor="tomcatThreadPool" protocol="org.apache.coyote.http11.Http11NioProtocol"
 connectionTimeout="5000" keepAliveTimeout="5000" maxKeepAliveRequests="100"
 acceptCount="200" maxConnections="10000" URIEncoding="UTF-8"/>

maxThreads 从 CPU×(1+等待/计算比)起步，但必须小于数据库与下游连接池容量；acceptCount 只是队列，不能掩盖慢请求。

保护与会话

启用 AccessLog 采样、JMX 和 Micrometer；上传限制、请求超时和拒绝策略显式配置。集群将 session 外置到 Redis/数据库，避免本地粘滞。

参考资料

  • Tomcat HTTP 配置
  • Tomcat 性能 FAQ
  • 阿里云 Tomcat 优化

Ansible 配置

- hosts: tomcat
  become: true

        path: "{{ tomcat_home }}/conf/server.xml"

MongoDB 调优篇：WiredTiger 缓存、索引与连接池

发表于 2024-10-03 | 分类于 调优 ， 数据库

MongoDB 7.x 的 WiredTiger 已较稳健，调优重点是工作集、索引选择性、写关注级别和连接池。副本集先保证多数派写入，再讨论吞吐。

mongod.conf 基线

storage:
  wiredTiger:
    engineConfig:
      cacheSizeGB: 12
operationProfiling:
  mode: slowOp
  slowOpThresholdMs: 100
net:
  maxIncomingConnections: 20000
replication:
  oplogSizeMB: 51200

WiredTiger cache 通常约为物理内存 50%（容器按 limit 计算），其余留给文件系统缓存和连接。驱动 maxPoolSize 从 100–200 起步，结合排队时间调节。

查询与索引

db.orders.explain('executionStats').find({tenantId:1,status:'PAID'}).sort({createdAt:-1})
db.orders.getIndexes()
db.serverStatus().wiredTiger.cache

复合索引遵循 ESR（Equality、Sort、Range）；分页采用范围条件避免高 skip。批量写使用 bulkWrite，并评估 w: majority 的延迟成本。

Elasticsearch 调优篇：堆内存、分片与刷新策略

发表于 2024-07-25 | 分类于 调优 ， 搜索

Elasticsearch 8.x 受 JVM 堆、磁盘 I/O、分片数量和查询模式共同影响；经典基线是堆不超过 31GB、约占物理内存一半。

节点与 JVM

# JVM 堆配置文件
-Xms16g
-Xmx16g
# Elasticsearch 配置文件
bootstrap.memory_lock: true
indices.memory.index_buffer_size: 15%
indices.queries.cache.size: 10%

分片大小建议 20–50GB，采用 ILM 做 Hot/Warm/冷分层；Bulk 从 5–15MB 起步，观察 rejected。

写入与查询

PUT logs-*/_settings
{"index":{"refresh_interval":"30s","number_of_replicas":1}}
GET _nodes/stats/jvm,fs,thread_pool
GET _cluster/health?level=shards

导入期间 refresh_interval 可调至 30s，完成后恢复 1s；深分页改用 search_after，映射严格控制高基数字段。

RocketMQ 调优篇：刷盘、堆外与消费者并发

发表于 2024-06-20 | 分类于 调优 ， 消息队列

RocketMQ 5.x 调优围绕 CommitLog 顺序写、PageCache、副本策略和消费并发；Broker 磁盘优先 NVMe/高性能云盘并与系统日志隔离。

Broker 参数

brokerRole=ASYNC_MASTER
flushDiskType=ASYNC_FLUSH
transientStorePoolEnable=false
mapedFileSizeCommitLog=1073741824
sendMessageThreadPoolNums=16
osPageCacheBusyTimeOutMills=1000

强一致场景改用 SYNC_MASTER+SYNC_FLUSH；普通事件可异步刷盘并依赖多副本。Producer 超时 3s、重试 2 次，批量消息控制在 1MB 内。

消费闭环

flowchart LR P[Producer批量/压缩]-->B[CommitLog顺序写] B-->R[副本同步/刷盘] R-->C[Consumer并发] C-->M[堆积与延迟监控]

消费者并发从 CPU×2 起步，顺序消息同队列单线程；监控 TPS、落盘延迟、重试主题和磁盘水位。
